# AI-Powered Technical Interview Platform

An end-to-end, RAG-driven application designed to automate technical screening interviews. The system intelligently extracts skills from a candidate's resume, utilizes a specialized domain knowledge base to dynamically generate contextual interview questions, and provides a structured AI evaluation of the candidate's performance.

## System Architecture

The application is built using a modern, decoupled client-server architecture:

- **Frontend:** Built with React (Vite), TypeScript, and Tailwind CSS. It provides a responsive, state-driven interface for resume upload, real-time Q&A interaction, and performance summary visualization.
- **Backend:** Built with Python and FastAPI. It exposes RESTful endpoints to handle file ingestion, state management, and interaction with the LLM.
- **Database:** PostgreSQL is used as the primary relational database to persist interview sessions and question-answer pairs via SQLAlchemy ORM.
- **Vector Store:** ChromaDB is implemented as a local vector database to store and retrieve embedded chunks of domain-specific knowledge. It is explicitly configured to use **Cosine Similarity** (`hnsw:space: cosine`) for highly accurate semantic matching.
- **Embeddings:** Uses the open-source `all-MiniLM-L6-v2` model via HuggingFace and Sentence Transformers for local, offline embedding generation, ensuring data privacy and removing API cost dependencies.
- **LLM Integration:** Google Gemini (via LangChain) powers the reasoning engine for skill extraction, question generation, and session evaluation.

## Core Features

- **Automated Resume Parsing:** Extracts core technical skills and domain exposure from uploaded PDF resumes.
- **Retrieval-Augmented Generation (RAG):** Instead of relying on generic LLM training data, questions are generated by retrieving highly relevant context from the local ChromaDB vector store based on the candidate's extracted skills and target role. The retrieval mechanism leverages **Cosine Similarity** against locally generated HuggingFace embeddings for precise context matching.
- **Stateful Interview Sessions:** The system maintains session continuity, ensuring progressive questioning without repetition.
- **Graceful Degradation:** Implements fallback mechanisms and mock generation logic to ensure continuous operation even if external API rate limits are exhausted.
- **Automated Evaluation:** Generates a comprehensive Markdown-formatted summary of the candidate's performance, highlighting key strengths, areas for improvement, and a final hiring recommendation.

## Prerequisites

- Python 3.9+
- Node.js 18+
- PostgreSQL Server
- Google Gemini API Key

## Local Environment Setup

### 1. Database Configuration
Ensure PostgreSQL is running locally. Create a database named `interview_db`.

### 2. Backend Setup
Navigate to the backend directory, install dependencies, and configure environment variables.

```bash
cd backend
python -m venv venv
venv\Scripts\activate  # On Windows
pip install -r requirements.txt
```

Create a `.env` file in the `backend` directory based on the provided `.env.example`:
```
GEMINI_API_KEY=your_gemini_api_key_here
DATABASE_URL=postgresql://username:password@localhost:5432/interview_db
```

To ingest the knowledge base into the vector store:
```bash
python ingest.py
```

To start the FastAPI server:
```bash
uvicorn app.main:app --reload
```
The backend will be available at `http://localhost:8000`.

### 3. Frontend Setup
Navigate to the frontend directory, install dependencies, and start the Vite development server.

```bash
cd react-frontend
npm install
npm run dev
```
The frontend will be available at `http://localhost:5173`.

## Usage Flow

1. Access the frontend application and input the candidate name and target role.
2. Upload a PDF resume. The backend will parse the document and extract relevant skills.
3. The system queries the vector database using the extracted skills to generate a highly specific, context-aware technical question.
4. The candidate submits their response via the split-screen interface.
5. This process repeats for a configurable number of iterations.
6. Upon completion, the system evaluates the entire transcript and displays a structured performance review.
